Turn 3 · implementation handoff · prototype vs production

What this prototype asserts, and what production must implement

Design intent, not a shipped contract. Where the prototype simplifies for demonstration it says so.

Concern
In this prototype
Required in production React
State model
Local component state: mode (choice / guided / free), step 1–6, arm, panel (single-occupancy), strat 0–3, phase 0–3, reduced.
Same names, but the semantic state id is the source of truth and must round-trip the deep link ?run=&proof=&state=&event= per cockpit/state-manifest.json. Guided steps need their own guide.* state ids; a mismatched proof and state resolves to run.missing, never a substitution.
Frozen fields
Three arms transcribed from experiments/hac-330/evidence/arms.json: decision, reason, detail, basisRevision, outcome expression, holds, verdict, coupling support 8/10, files, bound 130, checks 24/24, pins.
Read the same fields through media/hac-341/evidence/view-model.json and lib/arm-view.mjs. No value is derived in the component. An absent field renders as a visible [BIND: …] defect, never a blank or a default.
Focus behavior
Opener stored on open; focus moves to the panel Close control after 30ms; Escape or Close restores focus to the opener. Panels are single-occupancy.
Replace the timeout with a ref and a layout effect. Panels are non-modal role="complementary" regions: no focus trap, no inert on the run, no aria-modal. Step changes move focus to the step heading without scrolling evidence out of view.
Keyboard
Left / Right are scoped to the step rail group and the strategy group only. Escape is the one global key. Back / Next are the universal path and never depend on arrow keys.
Keep the scoping. Add roving tabindex inside both groups, Home / End to first and last, and confirm no arrow interception while focus is inside a scrollable proof region or any text field.
Timers
Ablation stages at 20 / 200 / 380ms (evidence, decision, outcome), inside the 700ms ceiling; intent B resolves 90ms after intent A. Every timer is cleared on the next interaction, so the sequence is interruptible and reversible. Nothing auto-advances.
Drive the same cadence from tokens/motion.css and components/motion/phases.js rather than literals. Cancel on unmount and on arm change. No animation may gate selection, copying or verification.
Reduced motion
The system preference wins and the control tells the truth about it. With prefers-reduced-motion: reduce active, the manual toggle is withdrawn and replaced by a status reading "Reduced motion · system preference", described as honouring the system setting; no "Enable motion" action is offered that the preference would override. Without the preference, the button names the action available (Reduce motion / Enable motion) and carries aria-pressed. When reduced, staged transitions become immediate state swaps and the changed / held-constant markers stay on screen.
Same substitution, plus: draw connectors immediately, open panels instantly, keep the step sequence, copy and count identical. Never fade essential content through low-opacity intermediates. Announce arm, decision, outcome and proof-class changes through one polite live region.

Out of scope this pass and unchanged: Google Cloud participation (class B), L3 raw proof, and degraded / unavailable / unbound states. Their entry points stay where the cockpit puts them.
