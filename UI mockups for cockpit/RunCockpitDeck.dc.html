Choreography and constraints

for implementation in Motion for React
07 · The Run · HAC-341
Choreography for Motion for React
t1 evidence row: opacity 1 → 0.55, y 0 → -2, 140ms ease-exit t2 gate terminals: gap 5 → 21px, 520ms ease-mech t2 token: outgoing y → -6 fade 0.35, incoming y 6 → 0 t2 primary slot: border ink → failed, 220ms ease-standard t3 hold 700ms: no transform, no opacity, no colour t4 terminals: gap 21 → 5px, 380ms, elevation back to elev-2
Rules it obeys
  • Passage never begins in the frame the aperture opens.
  • The hold is never shortened to tighten a capture.
  • No frame rests open. The gate re-arms.
  • No loops, no streaming, no simulated progress.
  • Reduced motion renders t0 beside t4, values struck in place.

The one genuine UX decision

overlay drawer against anchored disclosure
13 · The Run · HAC-341
Argues for anchored disclosure
  • Evidence and decision are visible in one frame, so attribution needs no memory.
  • No occlusion, no focus trap, no escape contract.
  • One screenshot carries L1 and L2 together.
Argues against it
  • The outcome numerals drop from 34px to 20px, weakening the protagonist.
  • Three columns at 1280 is too tight, so the fold contract needs a second layout.
  • L1 stops reading as calm: density arrives before it is asked for.
Recommendation

Keep the overlay drawer. It preserves the numeral scale that makes the delta the visual protagonist and holds one fold contract at both gates. Revisit the anchored variant only if 1440 stops being the review size.
